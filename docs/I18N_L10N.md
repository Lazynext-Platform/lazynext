# Internationalization and Localization

Lazynext Operating System ships with full internationalization (i18n) and
localization (l10n) support across 13 locales, covering translation,
pluralization, date/number formatting, currency display, timezone handling,
and regional format conventions.

## Supported Locales

Lazynext supports 13 locales, each with a complete translation file under
`src/i18n/locales/`:

| Code | Language | Script | Direction | File |
|------|----------|--------|-----------|------|
| `en` | English | Latin | LTR | `en.ts` |
| `zh` | Chinese (Simplified) | Han | LTR | `zh.ts` |
| `ja` | Japanese | Kana/Kanji | LTR | `ja.ts` |
| `es` | Spanish | Latin | LTR | `es.ts` |
| `ko` | Korean | Hangul | LTR | `ko.ts` |
| `pt` | Portuguese | Latin | LTR | `pt.ts` |
| `fr` | French | Latin | LTR | `fr.ts` |
| `de` | German | Latin | LTR | `de.ts` |
| `ar` | Arabic | Arabic | RTL | `ar.ts` |
| `hi` | Hindi | Devanagari | LTR | `hi.ts` |
| `vi` | Vietnamese | Latin | LTR | `vi.ts` |
| `th` | Thai | Thai | LTR | `th.ts` |
| `id` | Indonesian | Latin | LTR | `id.ts` |

Each locale file is a TypeScript module exporting a nested dictionary of
translation keys. The English locale (`en.ts`) is the canonical source;
other locales are translated from it.

## i18n vs l10n Separation

Lazynext distinguishes internationalization (i18n) from localization (l10n)
to keep concerns clean:

### Internationalization (i18n)

i18n covers the infrastructure that makes the application adaptable to
different languages and regions without code changes:

- **Translation**: All user-facing strings are keyed, not hardcoded.
  Translations live in `src/i18n/locales/<locale>.ts`.
- **Pluralization**: Locale-aware plural rules using the `Intl.PluralRules`
  API. Plural categories (one, few, many, other) are selected per locale.
- **Date formatting**: `Intl.DateTimeFormat` with locale-specific patterns.
  Short, medium, and long date formats are available.
- **Number formatting**: `Intl.NumberFormat` for digit grouping, decimal
  separators, and significant digits.
- **String interpolation**: Named placeholders (`{name}`, `{count}`) with
  type-safe parameter validation.

### Localization (l10n)

l10n covers region-specific business and legal adaptations:

- **Currency display**: ~30 currencies supported via `Intl.NumberFormat`
  with `style: 'currency'`. Currency is selected per user/org, not per
  locale (e.g., a German user may bill in USD).
- **Tax handling**: Region-specific tax rules applied at checkout.
- **Payment methods**: Available payment providers vary by region
  (Dodo Payments supports different methods per country).
- **Address formats**: Locale-aware address field ordering and validation.
- **Legal requirements**: Privacy policy, terms of service, and compliance
  pages are localized per jurisdiction where applicable.

## Dynamic Locale Loading

Locale dictionaries are loaded dynamically to keep the initial bundle small.
Only the active locale's translation file is included in the served bundle.
The loading mechanism uses dynamic `import()` so that unused locale files
are tree-shaken from the critical path.

## Locale Routing

Lazynext uses a dual-strategy locale routing system:

### Cookie-based routing

The user's selected locale is persisted in a cookie. On every request, the
server reads the cookie and applies the corresponding locale before
rendering. This ensures the locale is available during server-side render
(SSR) without waiting for client hydration.

### Path-based routing

Locale can also be specified via the URL path (e.g., `/ja/dashboard`).
Path-based locale takes precedence over the cookie, allowing shareable
localized links. When a path-based locale is detected, the cookie is
updated to match.

## RTL Support

Arabic (`ar`) is rendered right-to-left. The application sets `dir="rtl"`
and `lang="ar"` on the `<html>` element when the active locale is Arabic.
All layout components use logical properties (`margin-inline-start`,
`padding-inline-end`, etc.) rather than physical properties (`margin-left`,
`padding-right`) so that RTL and LTR layouts are mirror images without
separate stylesheets.

The Neo-Brutalist design system is fully RTL-compatible: borders, shadows,
and decorative elements flip correctly. Safe-area utilities
(`pt-safe`, `pb-safe`, `safe-top`, `safe-bottom`, `safe-area`) work in
both directions.

## Hydration-Safe Server-Side Locale Detection

A common pitfall in SSR frameworks is locale mismatch between server and
client, causing hydration errors. Lazynext avoids this by:

1. Detecting the locale on the server (from cookie or path) before render.
2. Passing the locale and its translations into the initial server-rendered
   HTML as serialized data.
3. Initializing the client-side i18n provider with the same locale and
   translations from the serialized data, ensuring the first client render
   matches the server render exactly.
4. Only switching locales after hydration is complete, via an explicit
   user action that triggers a full re-render.

This eliminates hydration warnings and flash-of-wrong-locale.

## Locale Persistence

| Mechanism | Storage | Lifetime | Purpose |
|-----------|---------|----------|---------|
| Cookie | Browser cookie | 1 year | Persist user's locale choice across sessions |
| URL path | Request URL | Per-request | Shareable localized links; overrides cookie |
| User profile | D1 database | Persistent | Default locale for authenticated users |

When an authenticated user changes their locale, the preference is saved
to their profile in D1. On next login, the saved locale takes precedence
over browser defaults.

## Currency Display

Lazynext supports approximately 30 currencies for billing and display:

| Currency | Code | Symbol | Example |
|----------|------|--------|---------|
| US Dollar | USD | $ | $19.99 |
| Euro | EUR | € | €19.99 |
| British Pound | GBP | £ | £19.99 |
| Japanese Yen | JPY | ¥ | ¥2,000 |
| Chinese Yuan | CNY | ¥ | ¥99.00 |
| Indian Rupee | INR | ₹ | ₹1,499 |
| South Korean Won | KRW | ₩ | ₩22,000 |
| Thai Baht | THB | ฿ | ฿699 |
| Vietnamese Dong | VND | ₫ | ₫499,000 |
| Indonesian Rupiah | IDR | Rp | Rp149,000 |

Currency formatting uses `Intl.NumberFormat` with the user's locale for
digit grouping and the selected currency for symbol placement. A German
user viewing USD prices sees `19,99 $` rather than `$19.99`.

## Timezone Handling

- All timestamps are stored in UTC in D1.
- Display timezones are resolved per user from their profile setting or
  inferred from the browser's `Intl.DateTimeFormat().resolvedOptions().timeZone`.
- Scheduled post times are stored in UTC and displayed in the user's
  local timezone for clarity.
- The cron trigger runs in UTC (`*/5 * * * *`).

## Adding a New Locale

1. Copy `src/i18n/locales/en.ts` to `src/i18n/locales/<code>.ts`.
2. Translate all string values.
3. Register the locale in the locale registry.
4. Add the locale to the locale switcher UI.
5. Add E2E smoke tests verifying key strings render in the new locale.
6. Verify RTL behavior if the locale is right-to-left.
