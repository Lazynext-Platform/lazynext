# ADR-018: Professional Export Formats

## Date
2026-08-28

## Status
Accepted

## Context
Rough cut plans generated by the editor are useful for planning, but professional video editors need to import the cut decisions directly into their NLE (non-linear editing) software. JSON-only export is not importable by Final Cut Pro, Premiere Pro, or DaVinci Resolve.

## Decision
1. Added 4 new export formats for rough cut plans:
   - **FCPXML** — Final Cut Pro 1.10 XML format (timecode-based)
   - **Premiere Pro XML** — xmeml interchange format (timecode-based)
   - **DaVinci Resolve XML** — frame-based XML format
   - **SRT** — subtitle file format (uses cut text as subtitle content)
2. All formats are generated server-side as strings in `src/lib/editor/transcript-cut.ts`
3. The existing `POST /api/editor/rough-cut` endpoint accepts a `format` parameter (`fcpxml|premiere|davinci|srt`) and returns the formatted output
4. No external libraries are used — all formats are constructed as template strings

## Consequences
- No external dependencies added — all formats are generated as plain strings
- FCPXML and Premiere Pro XML use timecode-based timing (HH:MM:SS:FF)
- DaVinci Resolve XML uses frame-based timing (frame numbers relative to a frame rate)
- SRT uses the cut text as subtitle content with sequential index entries
- Professional editors can import rough cut plans directly without manual re-entry
- The `format` parameter defaults to JSON for backward compatibility with existing clients
